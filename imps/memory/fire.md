- When both raw secrets are in hand (e.g. the `FIRE_API_KEY` env value and the request's bearer token), do not sha256 them before `timingSafeEqual`: CodeQL fails the PR with `js/insufficient-password-hash` (high), as on fire#542. Compare the raw buffers with a length check first: `const a = Buffer.from(token), b = Buffer.from(key); if (a.length !== b.length || !crypto.timingSafeEqual(a, b)) → 401` (the pattern in `app/routes/sync.js`). Hashing a supplied token to check it against a stored hash verifier is a different design and is fine.
